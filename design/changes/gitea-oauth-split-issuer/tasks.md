# Tasks

- [x] Add an optional server-side issuer override to `.env.template`, documented as falling back to `GITEA_ISSUER_URL` when unset. Implemented as `GITEA_BACKEND_HOST_OVERRIDE`.
- [x] Thread the override through `docker-compose.selfhost.yml` so the backend receives it (as an `extra_hosts` entry). `docker-compose.nas.yml` does not define the `backend` service, so there is nothing to thread there.
- [x] Confirmed upstream (the `gitea-oauth-native` backend fork) is not something this repository builds or can add a second issuer variable to — it only receives env vars this repo passes through. Implemented the host-mapping fallback instead: `GITEA_BACKEND_HOST_OVERRIDE` becomes a Docker `extra_hosts` entry, so `GITEA_ISSUER_URL` stays a single value and the backend's DNS resolution for that hostname is redirected. This preserves TLS SNI/certificate matching (a plain URL/IP substitution would not, per the brief). No backend code change needed.
- [x] Add a deploy-time reachability check for the OAuth back-channel, executed **on the deployment target**. Implemented as `gitea_backchannel_status()`: reads `GITEA_ISSUER_URL` / `GITEA_CLIENT_ID` / `GITEA_BACKEND_HOST_OVERRIDE` back from the target's `.env`, then runs a pinned `curlimages/curl` in a throwaway `--rm` container on the `multica_default` Docker network (not `docker exec` into the backend container itself, since that image is an external build this repo does not own) to probe the token-exchange address, applying `curl --resolve` when the override is set. Returns `not_configured` cleanly when Gitea login isn't set up.
- [x] Surface the check in deployment output and in the status command; do not report a deployment as complete when the back-channel is unreachable. `deploy`/`upgrade` and the `gitea` wizard now raise before printing their success line when the probe reports `unreachable`; `status` fails the same way `/readyz` already does (both are load-bearing checks); `doctor` only prints `gitea_backchannel=...` without failing, matching its read-only-diagnostic contract. Covered by 4 new tests in `test_multica_deploy.py`.
- [x] Documented the recreate-not-restart requirement: `update_backend_env()` already force-recreates the backend for every wizard-driven change (unaffected by this feature), and the README Gitea section now says so explicitly for anyone editing `.env` by hand.
- [x] Regression: verified by construction — `docker-compose.selfhost.yml`'s `extra_hosts` entry defaults to an inert placeholder (`unused.invalid:127.0.0.1`) when `GITEA_BACKEND_HOST_OVERRIDE` is unset, and `test_multica_deploy.py` asserts both the default and the override are present in the template/compose files.
